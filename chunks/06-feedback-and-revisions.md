# Chunk 06 - Feedback And Revisions

Status: Not started

Goal: Track reactions, requested changes, and revision decisions after the first mockup exists.

Why this matters: Keeping feedback in one place prevents design decisions from getting scattered across chat.

## Feedback Log

- User liked the first visual mockup and said, "this is fantastic!"
- User suggested that collectible objects should be picked up automatically when the character gets close or runs over them.
- User suggested that bringing parts to the broken machine should trigger repair when close, but possibly with a simple puzzle instead of instant auto-fix.
- User suggested a simpler repair-flow direction: instead of picking up required parts, the player receives a notice that something is down, goes to that scene, and solves a puzzle to fix it.
- User suggested that each scene's repair puzzle can get harder and harder.
- User liked the mockup as-is and requested occasional sky flashes followed by low rumbling thunder.
- User provided `Thunder.mov` to use as the thunder recording.
- User decided the personal recording had too much ambient noise.
- User downloaded a cleaner Pixabay thunder file: `freesound_community-thunder-single-long-rolling-distant-light-rain-toronto-2011-25157.mp3`.
- User requested lightning/thunder to happen randomly every 3 to 5 minutes instead of frequently.
- User revised the lightning/thunder timing to happen randomly every 1 to 3 minutes.

## Revision Decisions

- Adopt automatic pickup for loose repair parts.
- Use proximity to trigger the water wheel repair opportunity.
- Prefer a small simple repair puzzle for the water wheel instead of instant auto-repair.
- Revise the main repair flow toward repair notices plus on-site repair puzzles. Keep pickups optional rather than required for every repair.
- Adopt a gradual puzzle difficulty curve, adding one new puzzle idea per scene.
- Add occasional lightning flashes to the visual mockup.
- Add optional low thunder audio after the user enables sound in the browser.
- Use the downloaded Pixabay thunder file as the primary thunder sound, with generated thunder only as a fallback.
- Make storm events rare but noticeable: randomly timed every 1 to 3 minutes.
